# 物理世界的漂移：为什么"数据对不对"是个错误的问题

> 来源：用户 2026-09-28 的一句纠正。
> 当时我正在证明一个 agent 报告里的数字是错的（它说 14,040，实际 14,039）。
> 用户说：**追究真假没有多大意义。**

---

## 一、用户的原始观察

> **「真实的物理世界，首先人工会有错误，其次，更新迭代跟不上。**
>
> **例如，很多空间数据，开业几年了，但数据还在开业的时候，实际空柜可能超过一半，**
> **然后『有数据』的那一半，有些是已经关掉了，**
> **然后『没数据』的那一半，可能是八九月份新开的柜，但高德没有更新。」**

**★ 这段话包含四个独立的事实，每一个都足以推翻"数据质量"这个框架：**

| # | 事实 | 对分析的含义 |
|---|---|---|
| 1 | 人工录入本身有错 | 不是更新滞后，是**一开始就不准** |
| 2 | 更新迭代跟不上物理变化 | 时间越久偏得越多 |
| 3 | 已关闭的店仍在数据里 | **高估**活跃度 |
| 4 | 新开的店不在数据里 | **低估**活跃度 |

---

## 二、"追究真假"错在哪

我当时在做的事：证明 `map_data.js` 有 14,039 条而不是 14,040 条，没有伪对象。

**★ 这件事本身没错 —— 但它是个**小**问题。真正的问题是：**

```
14,039 这个数字是对的
而其中每一条记录的"内容"，都可能是某个过去时刻的快照
且偏差方向是一致的（高估活跃度）
```

**★★ 所以在数据上"对"，和在物理世界上"准"，是两件事。而后者无法通过校验数据得到。**

---

## 三、时间戳救不了：它测的不是物理变化

高德每条 POI 都带 `timestamp`（最后更新时间）。实测：

```
有 timestamp        13,977 / 13,981 = 100.0%
时间跨度            2025-10-27 → 2026-08-13

按月分布
  2026-06   1,834
  2026-07   2,867
  2026-08   8,832    ← 63% 是 8 月更新的
```

**★★ 数据看起来"很新"。但——**

> **那个时间戳是「高德什么时候动过这条记录」，不是「那个场什么时候变过」。**

**★★★ 一个 2020 年开业的场，租户结构停在 2021，只要高德在 2026-08 因任何原因碰过一次这条记录（改了个电话、补了张图），时间戳就是 2026-08。**

**所以时间戳在这里是一个**误导性的新鲜度信号** —— 它比没有更糟，因为它让人以为可以据此筛掉旧数据。**

---

## 四、致命后果：新场和衰败场在数据里长得一样

```
正在衰败的老场    品牌多（闭店还没传播）   ← 看起来繁荣
刚刚开业的新场    品牌少（入驻还没传播）   ← 看起来萧条
```

**★★ 两者的数据形态完全相同，而物理现实相反。**

**★★★ 这直接影响报告里的 Layer 4 和 Layer 5：**

| 层 | 被污染的方式 |
|---|---|
| Layer 4 相似度模型 | "条件相似的商场"里，新场和衰败场被算成同一类 |
| Layer 5 十大指数 | 分数是**跟同类比**得出的 —— 而参照系本身混了两类反向实体 |
| Layer 6 招商缺口 | "同类 81% 有儿童业态" —— 如果那个 81% 里混着数据陈旧的老场，结论就不成立 |

**★★★★ 也就是说：算出来的可能不只是商场质量，还有**数据的年龄**。而两者无法从数据里分离。**

---

## 五、这是"隐蔽型"的极端形态

回顾用户 `[RULES]` 里的分类：

```
致命型：违反会导致进程终止或系统崩溃        → 看得见
隐蔽型：违反不报错，但产生错误结果          → 看不见
```

**★ 物理世界的漂移是**第三个类别**，比隐蔽型更隐蔽：**

| | 数据错了 | 物理漂移 |
|---|---|---|
| 有没有报错 | 没有 | 没有 |
| 能不能靠校验发现 | **能** —— 内部一致性、格式、数量 | **不能** —— 数据完全自洽 |
| 能不能靠交叉验证发现 | 能 —— 对另一个数据源 | **不一定** —— 两个源可能都滞后 |
| 修得掉吗 | 能 —— 清洗、重抓 | **修不掉** —— 只能建模或绕开 |

**★★ 所以 dsh-steward 需要第三条约束，与已有两条并列。**

---

## 六、那能做什么

**① 不要把"数据"当作"事实"，把它当作"某个时刻的观测"**

每一条记录应该带两个时间：
- **记录的时间**（`timestamp`，已有）
- **它描述的事物的时间**（★ 没有，且拿不到）

**★ 第二个拿不到，所以**任何基于这类数据的结论都必须声明它假设了"记录时间 ≈ 事物时间"**，而这个假设在物理世界不成立。**

**② 用**变化的方向**而不是**绝对值**做分析**

绝对品牌数不可信。但"同一条记录在两次抓取之间**变了**"是可信的 —— 因为高德主动改动它，说明物理世界确实发生了值得它改的事。

**★★ 这意味着：多次抓取的**差异**比单次抓取的**快照**有价值得多。而这个项目已经有备份链（`amap_spatial_data.bak.json` / `bak2.json` / `bak_national_0813_1119.json`）—— **那些备份是被当作"防丢"用的，其实它们是唯一可信的信号源。**

**③ 把不可知的部分标出来，而不是填一个值**

Layer 5 的十大指数现在是 0–100 的确定分数。按用户的分析，其中"品牌数"相关的维度应该带一个**不确定度**，而不是一个点值。

**★ 而报告里那段"因为可拆解所以更诚实"的论证，恰好可以扩展到这里：**
> 商业成熟度 92 分，为什么？因为 POI 密度排前 15%，业态丰富度排前 20%。

**★★ 可以再加一句：**
> **而业态丰富度这一项，数据最后更新于 2026-08，记录的是 2020 年开业的租户结构，**
> **实际空柜率未知。**

**④ 设计上：不要把"数据质量"做成一个可以"修好"的状态**

**★★★ dsh-steward 该记住的是：这类系统永远达不到"数据是准的"这个状态。所以它的检查不能是"数据准不准"，只能是"我们知不知道它有多不准"。**

---

## 七、这条对 dsh-steward 本身也成立

**★ 因为 dsh-steward 也在处理"物理世界的观测"：**

```
它检查 dsh 能不能起来     → 测的是"上一次配置下的行为"
它检查 vecmem 一致性      → 测的是"文件之间的关系"，不是"记忆对不对"
它检查恢复路径可用        → 测的是"路径存在"，不是"恢复会成功"
```

**★★ 而且它同样是滞后、有方向、无法自证的：**

**2026-09-28 那天七个 bug 全部通过检查 —— 因为检查测的是"当前状态"，而 bug 在"未来的某条路径"上。**

**★★★ 这和"空间数据的数据还停在开业时"是**同一个结构**：**

> **观测到的，是观测那一刻的快照；而决定结果的，是快照之后发生的事。**

**★★★★ 所以第五条约束可以写成一句通用的话：**

> **任何基于观测的结论，都必须声明它假设了什么没有变。**
> **在一个会变的物理世界里，这个假设迟早不成立 —— 设计要做的是让假设显式，而不是让它永远成立。**

---

## 八、一句话

**用户的原话比我这份文档的任何一句话都准：**

> **追究真假没有多大意义。**

**★ 有意义的是：知道偏差朝哪个方向、有多大、以及**哪些结论碰不得它**。**
