## 二、记录在案的三个缺口，全部解决

### 2.1 重庆 = 0 条

**根因**：`city=重庆` 全市搜索，高德对直辖市返回异常。
**修复**：按 37 个区县分别拉取 → **300 条**。

### 2.2 深圳缺南山区（0 条）

**根因**：`city=深圳市` 全市搜索 + 高德对"区名"作 city 参数（citylimit）返回 0，南山区 POI 整片漏掉。
**修复**：按 9 区 adcode 精确拉取 → **301 → 361 条**
```
宝安69 南山61 龙岗61 龙华52 福田47 罗湖40 光明11 坪山11 盐田9
count 验证：各区 adcode 精确 count=366，可翻页去重=361
           （count 含重复/无坐标 POI，虚高 5 条，非缺口）
```

### 2.3 ★ 深化索引错位 —— 与今天 vecmem 那个 bug 同型

**根因**：`mall_deepen_result.json` 与 `amap_mall_data.json` 是**按扁平顺序**对应的（无 id）。
补采深圳 61 条**插在中部**，顺序从某 idx 起漂移 1 位，**后续全局偏移，name 不匹配数百条**。

**SOP 里写下的结论**：
> **禁止靠顺序对齐重建。**
> 靠"剔除新增后 vs 旧版本比对"也不可靠（起点就错位）。
> **可靠方法 = 按 POI 的 id 映射。**

**修复**：`rebuild_deepen_res.py` 用 POI_ID 重映射 → 13,901 条，缺深化 0。
**校验**：重建后必须逐条 `res[i]['name'] == flat[i].name`，为 0 才算成功。

> ★ **今天修 vecmem 时，我用的是按位置拼**（idx 0..4617 取 `.f32`，4618..4999 取 `store.json`）。
> 它当时能成，是因为数量刚好对上（4618+382=5000）。
> **这份 SOP 一个月前就写明了按顺序会漂移。**

## 四、★ 这个项目证明的三件事

### 4.1 SOP 里的坑，全是"隐蔽型"

高德那四个坑，**没有一个会抛异常**：

```
① 200 条硬上限      count 显示真实总数，翻页只给 200 —— 返回成功
② 直辖市伪 district  city=北京城区 返回 count=0 —— 不报错，只是空
③ 区名作 city 参数   南山区整片漏掉 —— 数据看着完整
④ 顺序对齐漂移       索引错位数百条 —— 每条都"读到了"
```

**★★ 和 2026-09-28 那七个缺陷完全同型。那份 `[RULES]` 里给这一型起了名字：**

> **红线规则（隐蔽型）：违反不报错但产生错误结果**

### 4.2 ★★★ 沉淀的是知识，不是代码

```
memory/*.md    27 个 SOP   ← 永久（跨会话）
temp/*.py      9 个脚本    ← 一次性（SOP 原话："中间产物用完即删"）
```

**★★ 这是刻意的分工，而且分工线画得很准：**

| | 去哪 | 为什么 |
|---|---|---|
| **API 的坑、前置条件、典型错** | `memory/*_sop.md` | 跨会话仍重要，难以用几步探测重建 |
| **爬取脚本本身** | `temp/` | 可复现，下次照 SOP 重写 |
| **原始数据 + 备份链** | `temp/*.json` | 资产，分级备份 |
| **成品** | 根目录 / `.sciforge/` | 交付物 |


> **L3 记录原则**：只记录**跨会话**仍重要、且难以通过少量 `file_read` / `web_scan` / 简单脚本快速重建的要点。
> **不记录**：普通操作步骤、可在几步探测中重新获得的路径或状态信息。

### 4.3 ★★★ 跨工具链，各做各擅长的

```
采集脚本          采集      调高德 API · 369 城 · 13,981 条
   ↓ 数据
得到大脑           报告      会议记录 → 叙事文档（12,274 字 · 11 页）
   ↓ 文本
sciforge          排版      PDF + PPTX
```

**★ 三个工具，没有一个是"万能"的，而链条是通的。**

**而报告里那段关于"为什么不再扩数据了"的论证，恰好是三根支柱的第一根：**

> **「数据量在涨，但认知没在涨。」**

## 五、报告本身最值得抄的一段

Layer 5 讲十大指数时，有一段论证和一个完全不同的领域撞上了：

> **「评分这件事，问题不在于主观还是客观，在于可不可拆解。评分如果靠主观，它就只是一个意见，不是一个事实。」**
>
> **「专家的打分你没法质疑 —— 你只能说『我不同意』，他说『我同意我自己』，死循环。但算法的打分你可以拆开看：商业成熟度 92 分，为什么？因为 POI 密度排前 15%，业态丰富度排前 20%。你觉得权重不对？调。你觉得维度不该算？删。」**
>
> **「这比主观评分强太多了。**不是因为它更准** —— 算法的权重也是人设的，也可能设错。**而是因为它更诚实** —— 它把判断逻辑暴露在阳光下，谁都能质疑，谁都能改。」**

**★★★ 这段话和 `cordis-dsh-audit/invariants/run.mjs` 的自我说明是同一个论证：**

> *"A divergence is not automatically a bug on the line that failed: it is a question about which behaviour the property demands."*

**两个领域，同一句话：**不判决，但把推理暴露出来。** 不是因为它更准，是因为它更诚实。**

## 八、本次复盘新发现的三个问题（原复盘没有的）

### 8.1 ★★★ 源数据有跨城污染 —— 而 SOP 只记了它的另一半

```python
# 武汉市的 228 条里，有 5 条纬度 >39°：
九星国际广场                 adname=青山区  loc=109.866757,40.667920
BHG Mall北京华联包头购物中心    adname=青山区  loc=109.860371,40.657005
包头印象城                    adname=青山区  loc=109.940801,40.643785
王府井百货(青山店)             adname=青山区  loc=109.880762,40.668619
万达广场(包头青山店)            adname=青山区  loc=109.853362,40.658539
```

**这 5 条在包头（40.66°N），不在武汉（30.59°N）。**

**根因：全国有 22 个区县名重复，而爬虫用 `city=<区县名>` 作查询参数。**

```
  鼓楼区  → 南京 · 开封 · 徐州 · 福州
  市中区  → 乐山 · 内江 · 枣庄 · 济南
  青山区  → 包头 · 武汉          ← 就是这一对
  新城区  → 呼和浩特 · 西安
  龙华区  → 海口 · 深圳
  白云区  → 广州 · 贵阳
  …  共 22 个
```

**★★ SOP 记录的是这个问题的**失败侧**：**

> `city=北京城区` 返回 **count=0**（伪名不可查）

**它没记录**污染侧**：**

> `city=青山区` 返回**两个城市的区** —— 不报错，数据看着完整

**★★★ 这正是用户 `[RULES]` 里那个分类的又一个实例：**

```
致命型：city=伪名 → count=0       失败看得见，当场发现
隐蔽型：city=重名 → 返回两个       不报错，混进后续所有分析 ★
```

**修复方向：用 `adcode` 查询，不用区县名。** `adcode` 全国唯一，没有这个问题。**
**而 SOP 里其实已经提到 adcode（深圳修复用的就是 `city=adcode+citylimit`）—— 但没有把它上升为通则。**

### 8.2 ★★ 地图数据丢了城市字段（57.3%）

`temp/map_data.js` 12.87 MB，14,039 条记录：

## 九、★ 这次复盘真正学到的一条

**这个项目的每一个坑，都指向同一件事：**

```
200 条上限          → 翻页"成功"了，只给了 200 条
伪 district         → count=0，不报错，只是空
重名区县             → 返回两个城市，数据看着完整      ★ 本次新发现
顺序对齐漂移          → 索引错位数百条，每条都"读到了"
城市字段 join 丢失    → 57% 为空，指数照样算出来了      ★ 本次新发现
```

**★★ 五个坑，五个都是隐蔽型。没有一个抛异常。**

**★★★ 而 SOP 里已经写下了防御的**方向**，只是在两处没有贯彻到底：**

| SOP 里的话 | 贯彻到了哪 | 没贯彻到哪 |
|---|---|---|
| 「可靠方法 = 按 POI 的 **id** 映射」 | 深化结果重建 | ★ 地图数据丢了 id |
| 「用 **adcode** 精确拉取」 | 深圳修复 | ★ 其他城市仍用区县名 |

**★★★★ 所以这条通则值得单独写出来：**

> **凡是跨阶段的连接键，必须是一个**全局唯一**的标识 —— id、adcode、坐标 —— 而不是名称、区县名、或顺序位置。**
> **用非唯一键做连接，失败是静默的：对得上的是对的，对不上的是错的，而两者看起来一样。**
